# 狒狒食柿 0.3.51 验证版

App、服务端均更新到 0.3.51，保留安装标识、签名与原授权。

- 人物移入“角色”的二级栏，与状态参数、个人信息、职业&特职、评价并列。
- 鼠标指针模式滑动松手不再点击：移动超过8像素或超过350ms不会触发轻点；取消手势也不会点击。触屏模式保留按住/松开行为。
- 新增可选 H.264 硬件串流：Windows Graphics Capture 采集游戏窗口，FFmpeg 使用所选显卡的 NVENC/AMF/QSV 编码；手机使用 MediaCodec 硬件解码与低延迟选项，不再通过 JPEG 请求循环传送这一模式的画面。实际可用性取决于显卡、驱动、手机解码能力和网络。
- 模块设置和面板中提供“串流显卡”，列出检测到的 NVIDIA、AMD、Intel 显卡；可手动选择核显或独显。硬件编码失败时显示错误，不静默回退软件编码。
- 视频连接沿用设备授权和证书固定；使用有界队列，积压后等待关键帧恢复，避免持续积累旧画面。全屏、小窗与 App 内分屏沿用原控制界面。
- 串流、人物预览和普通读取使用独立请求队列，显示兼容组件准备进度。
- 人物连续拖动及时发送旋转请求；图像优先 JPEG，活动预览按100ms目标节奏请求。读回设置3秒期限，停止可取消任务。
- 手机创建的原生角色窗口移到屏幕外，结束时恢复并关闭，避免仅外框透明而文字留在游戏中。玩家已经打开的角色窗口保持原状。

## 手动启用硬件串流

硬件串流默认关闭，模块不会自动安装或替换新硬件编码组件。原兼容 JPEG 组件仍为已校验的0.3.50版本。

1. 更新 App 和服务端后，手动下载本发布的 `StreamHost.exe`（仅用于硬件模式）。
2. 手动下载并解压 [FFmpeg 8.1.3 LGPL 构建](https://github.com/BtbN/FFmpeg-Builds/releases/download/autobuild-2026-10-14-13-03/ffmpeg-n8.1.3-18-g46d899d7a0-win64-lgpl-shared-8.1.zip)，保留 `bin` 中的 DLL 和 `ffmpeg.exe`。压缩包 SHA256：`38dd3fb973c2e10723489e2173135d60f569953e70a04b885446175f9e9380d6`。
3. 在模块“串流显卡”设置中填写这两个本地程序的完整路径，选择显卡，主动勾选“启用 H.264 硬件串流”，再从手机开始串流。

FFmpeg 来源、构建说明和 LGPL 许可：[BtbN/FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds)、[对应 FFmpeg 源码](https://github.com/FFmpeg/FFmpeg/tree/46d899d7a0)。本发布不重新分发该上游二进制包。

实现参考：Sunshine 的硬件编码、禁用重排和限制排队的设计，以及 Moonlight Android 的 MediaCodec 低延迟处理；本项目独立实现，未导入两者源码或宣称兼容 GameStream 协议。参考项目均为 GPL-3.0，链接见 `PhoneApp/STREAMING.md`。

已通过模块编译/源码兼容检查、33项键鼠/权限/关键帧队列检查、完整浏览器回归和 APK 签名验证；本机 RTX 3090 Ti 已实测硬件编码实际游戏窗口，H.264 数据包完整、可解码；当前游戏窗口3840×2088、目标60FPS/8M的短测约30.2FPS，编码首帧约655ms（不含手机和网络延迟）。
